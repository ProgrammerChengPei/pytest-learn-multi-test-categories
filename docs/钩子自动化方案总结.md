# 钩子自动化方案总结 / Hook-based Automation Summary

## 一、整体架构 / Overall Architecture

### 1.1 核心思想 / Core Idea

**将所有横切关注点从测试代码中提取到钩子中**

Extract all cross-cutting concerns from test code into hooks:

```
传统测试代码 / Traditional Test Code:
  +-------------+
  | 测试逻辑     |
  +-------------+
  | 依赖管理     | ← 手动编写
  +-------------+
  | 状态更新     | ← 手动编写
  +-------------+
  | 结果记录     | ← 手动编写
  +-------------+

钩子驱动测试代码 / Hook-driven Test Code:
  +-------------+
  | 测试逻辑     | ← 只关注业务逻辑
  +-------------+

钩子层 / Hook Layer:
  +-----------------------------+
  | pytest_sessionstart         | ← 自动初始化
  +-----------------------------+
  | pytest_runtest_logreport    | ← 自动收集结果
  +-----------------------------+
  | pytest_runtest_makereport   | ← 自动更新状态
  +-----------------------------+
  | pytest_runtest_setup        | ← 自动检查依赖
  +-----------------------------+
  | pytest_collection_modify    | ← 自动添加依赖标记
  +-----------------------------+
  | pytest_sessionfinish        | ← 自动生成报告
  +-----------------------------+
```

### 1.2 代码量对比 / Code Comparison

| 方案 / Approach | 每个测试代码行数 / Lines per Test | 100个测试总行数 / Total for 100 Tests |
|---------------|-------------------------------|-----------------------------------|
| 传统手动管理 / Traditional | ~15行 | ~1500行 |
| 钩子自动化 / Hook-based | ~3行 | ~300行 |
| **减少 / Reduction** | **80%** | **80%** |

```python
import pytest

class TestAPI:
    @pytest.mark.interface
    @pytest.mark.dependency(name="test_login", depends=["test_flash_complete"])
    def test_login(self, test_state, test_client):
        """登录测试 - 传统方式"""
        # 业务逻辑
        response = test_client.login("user", "pass")

        # 断言
        assert response.status_code == 200

        # 手动记录结果
        test_state.results["test_login"] = {
            "status": "passed",
            "duration": 0.123,
            "message": ""

        # 手动更新状态
        test_state.mark_interface_passed()

        # 手动添加到Excel报告
        test_state.excel_report.add_test_result({
            "name": "test_login",
            "category": "interface",
            "status": "passed",
            "duration": 0.123,
            "message": ""
        })

    @pytest.mark.interface
    @pytest.mark.dependency(name="test_logout", depends=["test_login"])
    def test_logout(self, test_state, test_client):

        # 先检查依赖

        # 断言
        assert response.status_code == 200

        # 手动记录结果
        test_state.results["test_logout"] = {
            "status": "passed",
            "duration": 0.089,
            "message": ""

        # 手动添加到Excel报告
```

## 五、钩子实现细节 / Hook Implementation Details

### 5.1 pytest_sessionstart

```python
def pytest_sessionstart(session):
    """
    测试会话开始时自动执行
    1. 创建reports目录
    2. 初始化Excel报告生成器
    3. 记录开始时间
    """
    from src.excel_report import ExcelReportGenerator

    # 创建报告输出目录
    output_dir = project_root / "reports"
    output_dir.mkdir(exist_ok=True)

    # 初始化报告生成器
    generator = ExcelReportGenerator(output_dir)
    generator.start()

    # 存储到session中供其他钩子使用
    session.config.excel_report_generator = generator
    session.config.session_start_time = time.time()
```

**关键点 / Key Points:**
- 只在会话开始时执行一次
- 将生成器存储在 `session.config` 中，其他钩子可以访问
- 自动创建输出目录

### 5.2 pytest_runtest_logreport

```python
def pytest_runtest_logreport(report):
    """
    每个测试完成后自动执行
    1. 提取测试信息（名称、状态、耗时等）
    2. 识别测试类型（flash/interface/function/performance）
    3. 自动添加到Excel报告生成器
    """
    # 只在测试完成时收集结果
    if report.when == 'call':
        generator = report.session.config.excel_report_generator

        # 识别测试类型
        test_type = None
        for marker_name in ['flash', 'interface', 'function', 'performance']:
            if report.node.get_closest_marker(marker_name):
                test_type = marker_name
                break

        if test_type:
            # 构建测试结果
            test_result = {
                'name': report.node.name,
                'category': test_type,
                'status': 'passed' if report.passed else 'failed',
                'duration': report.duration,
                'message': str(report.longrepr) if not report.passed else ''
            }

            # 自动添加
            generator.add_test_result(test_result)
```

**关键点 / Key Points:**
- 每个测试完成后执行
- `report.when == 'call'` 确保只收集最终结果
- 从 `report.passed` 获取状态
- 从 `report.duration` 获取耗时
- 从 `report.longrepr` 获取失败消息

### 5.3 pytest_runtest_makereport

```python
def pytest_runtest_makereport(item, call):
    """
    测试报告生成时自动执行
    1. 检查测试是否通过
    2. 获取test_state fixture
    3. 自动更新对应的测试完成状态
    """
    report = call.result if call else None

    if report and report.when == 'call' and report.passed:
        test_state = None

        # 获取test_state fixture
        try:
            if hasattr(item, '_fixtureinfo'):
                fixturedef = item._fixtureinfo.name2fixturedefs.get('test_state')
                if fixturedef:
                    test_state = fixturedef[0].cached_result[0]
        except Exception:
            pass

        # 自动更新状态
        if test_state:
            if item.get_closest_marker('flash'):
                test_state.mark_flash_passed()
            elif item.get_closest_marker('interface'):
                test_state.mark_interface_passed()
            elif item.get_closest_marker('function'):
                test_state.mark_function_passed()

    return report
```

**关键点 / Key Points:**
- 在测试报告生成时执行
- 通过 `_fixtureinfo` 获取fixture
- 从 `cached_result` 获取fixture的返回值
- 根据marker类型调用对应的 `mark_*_passed()` 方法

### 5.4 pytest_runtest_setup

```python
def pytest_runtest_setup(item):
    """
    每个测试运行前自动执行
    1. 检查测试类型
    2. 获取test_state fixture
    3. 检查前置测试是否通过
    4. 自动跳过未满足依赖的测试
    """
    # 识别测试类型
    test_type = None
    for marker in ['interface', 'function', 'performance']:
        if item.get_closest_marker(marker):
            test_type = marker
            break

    if not test_type:
        return

    # 获取test_state
    test_state = None
    try:
        if hasattr(item, '_fixtureinfo'):
            fixturedef = item._fixtureinfo.name2fixturedefs.get('test_state')
            if fixturedef:
                test_state = fixturedef[0].cached_result[0]
    except Exception:
        pass

    if not test_state:
        return

    # 检查依赖
    skip_reason = None
    if test_type == 'interface' and not test_state.flash_test_passed:
        skip_reason = "Flash test has not passed yet"
    elif test_type == 'function' and not test_state.interface_test_passed:
        skip_reason = "Interface test has not passed yet"
    elif test_type == 'performance' and not test_state.function_test_passed:
        skip_reason = "Function test has not passed yet"

    if skip_reason:
        pytest.skip(skip_reason)
```

**关键点 / Key Points:**
- 在测试运行前执行
- 根据测试类型检查对应的前置测试状态
- 自动调用 `pytest.skip()` 跳过未满足依赖的测试

### 5.5 pytest_collection_modifyitems

```python
def pytest_collection_modifyitems(config, items):
    """
    测试收集完成后自动执行
    1. 定义依赖映射
    2. 为每个interface/function/performance测试添加依赖标记
    3. 按测试类型排序
    """
    dependency_mapping = {
        'interface': 'test_flash_complete',
        'function': 'test_interface_complete',
        'performance': 'test_function_complete'
    }

    for item in items:
        # 检查测试类型并添加依赖标记
        for marker_name in ['interface', 'function', 'performance']:
            if item.get_closest_marker(marker_name):
                dependency_name = dependency_mapping.get(marker_name)
                if dependency_name:
                    item.add_marker(
                        pytest.mark.dependency(
                            depends=[dependency_name],
                            name=f"{marker_name}_auto_dep_{item.name}"
                        )
                    )
                break

    # 按测试类型排序
    phase_order = {'flash': 0, 'interface': 1, 'function': 2, 'performance': 3}

    def get_test_order(item):
        for marker_name, order in phase_order.items():
            if item.get_closest_marker(marker_name):
                return order
        return 99

    items.sort(key=get_test_order)
```

**关键点 / Key Points:**
- 在测试收集完成后执行
- 自动为interface/function/performance测试添加依赖标记
- 使用 `item.add_marker()` 动态添加marker
- 按阶段顺序排序测试

### 5.6 pytest_sessionfinish

```python
def pytest_sessionfinish(session, exitstatus):
    """
    测试会话结束时自动执行
    1. 停止计时器
    2. 生成带时间戳的Excel报告
    3. 计算并打印统计信息
    4. 显示报告路径
    """
    generator = getattr(session.config, 'excel_report_generator', None)
    session_start_time = getattr(session.config, 'session_start_time', None)

    if generator and session_start_time:
        generator.stop()

        # 生成带时间戳的报告文件名
        timestamp = datetime.now().strftime('%Y%m%d_%H%M%S')
        filename = f"test_report_{timestamp}.xlsx"

        # 自动生成报告
        report_path = generator.generate_report(filename)

        # 计算统计信息
        total_tests = len(generator.test_results)
        passed_tests = len([r for r in generator.test_results if r.get('status') == 'passed'])
        failed_tests = len([r for r in generator.test_results if r.get('status') == 'failed'])

        # 打印统计信息
        print(f"\n测试统计:")
        print(f"  总数: {total_tests}")
        print(f"  通过: {passed_tests} ({passed_tests/total_tests*100:.1f}%)")
        print(f"  失败: {failed_tests} ({failed_tests/total_tests*100:.1f}%)")
        print(f"  耗时: {generator.end_time - session_start_time:.2f}s")
        print(f"\n报告路径: {report_path}")
```

**关键点 / Key Points:**
- 在会话结束时自动执行
- 生成带时间戳的文件名，避免覆盖
- 自动计算并打印统计信息
- 显示报告保存路径

## 七、优势总结 / Benefits Summary

### 7.1 代码质量 / Code Quality

| 维度 / Dimension | 传统方式 / Traditional | 钩子方式 / Hook-based |
|----------------|----------------------|----------------------|
| 测试代码可读性 / Test Readability | 低（混杂大量样板代码） | 高（只关注业务逻辑） |
| 代码复用性 / Code Reusability | 低（每个测试重复代码） | 高（所有逻辑在钩子中） |
| 维护成本 / Maintenance Cost | 高（修改需要改所有测试） | 低（只需修改钩子） |
| 错误率 / Error Rate | 高（容易遗漏手动代码） | 低（自动化保证一致性） |

### 7.2 开发效率 / Development Efficiency

| 场景 / Scenario | 传统方式 / Traditional | 钩子方式 / Hook-based |
|----------------|----------------------|----------------------|
| 新增1个测试 / Add 1 test | ~15行代码，5分钟 | ~3行代码，1分钟 |
| 修改报告格式 / Modify report format | 需改所有测试 | 只改钩子 |
| 添加新的测试类型 / Add new test type | 需添加依赖代码 | 只添加marker |
| 调试测试问题 / Debug test | 需检查手动代码 | 只检查业务逻辑 |

### 7.3 可扩展性 / Scalability

| 指标 / Metric | 传统方式 / Traditional | 钩子方式 / Hook-based |
|----------------|----------------------|----------------------|
| 支持测试数量 / Supported tests | 受限于手动管理 | 无限制 |
| 新增报告格式 / New report format | 需大量修改 | 只需添加新钩子 |

```python
    request.node.user_properties.append(('value', f'{duration:.3f}s'))
```
